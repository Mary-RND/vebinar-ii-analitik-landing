# Публикация веб-версии дашборда на GitVerse Pages

Веб-версия дашборда — отдельный репозиторий из двух действующих файлов: страница входа
(`index.html`) и зашифрованный дашборд (`payload.bin`). Кода пайплайна, отчётов, Excel,
внутренних и ценовых документов там нет — публиковать этот репозиторий безопасно.

Папка готового репозитория: **`output/botkina-dashboard/`** (уже проинициализирован в git,
первый коммит создан).

---

## 1. Регистрация и подготовка

1. Войдите на [gitverse.ru](https://gitverse.ru) (вход через Sber ID).
2. Название аккаунта **не должно содержать точек** — это требование GitVerse Pages
   (от них зависит поддомен `<owner>.gitverse.site`). Если точка в логине есть —
   аккаунт нужно переименовать в профиле.
3. Название репозитория для сайта: **`botkina-dashboard`** (не начинать с точки).

## 2. Создать публичный репозиторий

1. **Новый репозиторий** → имя `botkina-dashboard`, описание — например
   «Интерактивный дашборд закупок МНКЦ им. С.П. Боткина за 2025 год».
2. Видимость — **публичный** (иначе Pages не включится: на тарифе Free сайты
   публикуются только из публичных репозиториев).
3. **Без** инициализации README (папка уже содержит свои файлы).
4. В настройках репозитория включить **CI/CD** — это обязательное условие Pages.

## 3. Отправить файлы

Откройте папку `output/botkina-dashboard` и выполните (вместо `<ЛОГИН>` — ваш логин GitVerse):

```
cd D:\Freelance\Yurchikova\Botkina\output\botkina-dashboard
git remote add origin https://gitverse.ru/<ЛОГИН>/botkina-dashboard.git
git push -u origin main
```

Если git попросит логин/пароль — используйте [Personal Access Token](https://gitverse.ru/-/user_settings/personal_access_tokens)
в роли пароля (галочки: `write_repository`), либо настройте SSH-ключ.

## 4. Включить публикацию

На странице репозитория: **Настройки → Страницы**

1. Включить GitVerse Pages.
2. Источник — **Ветка**.
3. Ветка — `main`, папка — `/` (корень).
4. Сохранить настройки.

Сборка запустится автоматически; статус и логи — в разделе CI/CD или на самой странице Pages.
Если встроенный сборщик по какой-то причине не отдаёт файл данных (в логах будет ошибка
на `payload.bin`) — переключите источник публикации на **workflow**: в репозитории уже лежит
готовый `.gitverse/workflows/publish-pages.yml`, он публикует файлы как есть, без сборщика.

## 5. Проверить

Сайт проекта открывается по адресу

```
https://<ЛОГИН>.gitverse.site/botkina-dashboard/
```

Ту же ссылку GitVerse показывает на главной странице репозитория в блоке Pages — оттуда
её удобнее всего скопировать и вставить в карточку доступа вместо `<ЛОГИН>`.

Проверочный сценарий:

| Шаг | Ожидание |
| --- | --- |
| Открыть ссылку | страница входа: название, поле пароля, кнопка «Открыть» |
| Пароль пустой | «Введите пароль» |
| Пароль неверный | «Неверный пароль. Проверьте раскладку клавиатуры и регистр.» |
| Пароль верный | открываются 9 разделов дашборда, KPI-карточки на месте |
| Фильтр (например «Вид закупки») | цифры и графики пересчитываются, появляются чипсы |
| Кнопка «Печать / PDF» | печатается сам дашборд, страница входа — нет |
| Файл `payload.bin` не отдаётся | «Не удалось загрузить данные дашборда (файл payload.bin недоступен)» — см. п. 4 |

Ссылку и пароль передать заказчику удобнее всего готовой карточкой
`output/Доступ_к_веб_дашборду.txt` (файл создаётся при сборке и в git не попадает).

---

## Как устроен пароль

| Параметр | Значение |
| --- | --- |
| Шифрование | AES-256-GCM (данные дашборда лежат в `payload.bin` в зашифрованном виде) |
| Вывод ключа | PBKDF2-HMAC-SHA-256, 250 000 итераций |
| Соль | 16 байт, новая при каждой сборке |
| Где живёт пароль | ни в одном файле сайта; проверяется и расшифровка — в браузере посетителя |

Что это даёт:

- репозиторий и страница публичные, но без пароля данные не читаются — даже скачав
  `payload.bin` напрямую;
- сервер GitVerse не хранит пароль и не хранит открытые данные.

Чего это **не** даёт (честные ограничения статической защиты):

- кто знает пароль, может открыть дашборд, сохранить его локально или распечатать;
- пароль один на всех, истории входов и разграничения прав нет;
- при очень простом пароле перебор возможен, поэтому используется пароль длиной
  от ~12 символов со случайными знаками;
- поисковые системы не индексируют страницу входа (`noindex`), но это защита от
  индексации, а не от доступа.

## Смена пароля

```
cd Yurchikova/Botkina
python pipeline/build_web.py --password "новый сложный пароль"
git -C output/botkina-dashboard add -A
git -C output/botkina-dashboard commit -m "chore: смена пароля доступа"
git -C output/botkina-dashboard push
```

Старый пароль перестаёт открывать данные (соль и ключ пересобираются). Карточку
`output/Доступ_к_веб_дашборду.txt` нужно обновить — для этого удобнее
`python _probe/make_web_repo.py` (пересобирает сайт, репозиторий и карточку одним шагом
с сохранённым паролем из `output/_password.tmp`, либо с новым, если переменную
`BOTKINA_WEB_PASSWORD` не задавать).

## Состав папки-репозитория

```
botkina-dashboard/
├── index.html                     # страница входа (7 КБ)
├── payload.bin                    # дашборд, AES-256-GCM (3,9 МБ)
├── README.md                      # описание для заказчика на самой странице репозитория
├── .nojekyll                      # отключает обработку статики сборщиком Jekyll
├── .gitignore
└── .gitverse/workflows/publish-pages.yml   # публикация без встроенного сборщика (запасной путь)
```

Сборка выполняется скриптом `pipeline/build_web.py` из готового `output/dashboard.html`;
сквозная проверка — `python _probe/test_web.py` (5 сценариев: пустой, неверный и верный
пароль, работа фильтров внутри раскрытого дашборда, отсутствие файла данных).
